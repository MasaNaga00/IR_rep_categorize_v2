## 1. 何が変わったか

充電器・バッテリーが原因の修理を、発生状況として把握できるよう、ML・DC に次のコードを追加した(YAML 0.5.3)。充電器・バッテリーは付属品なので、どのコードもユーザ責任(メーカー責任のカウントに入れない)。

| 原因 | コード(ML / DC) | 責任区分 |
|---|---|---|
| 純正の充電器の不良(バッテリーチャージャー、純正の USB 電源アダプターを含む) | 充電器不良 M051 / D051 | ユーザ責任 |
| 純正のバッテリーの不良(内部回路の不良、膨らみなど) | バッテリー不良 M052 / D052 | ユーザ責任 |
| バッテリーの劣化・寿命(容量の低下、買い替えのお勧めなど) | バッテリー劣化(寿命) M053 / D053 | ユーザ責任 |
| 他社製・互換品のバッテリー・充電器、USB 充電に使う汎用の充電器・ケーブル・モバイルバッテリー | 接続機器要因 M047 / D046(今までどおり) | ユーザ責任 |

- 純正か他社製かが書かれていない場合は、純正とみなす。
- 充電器・バッテリーだけが原因の修理は NO(代表故障は空)。カメラ本体の不具合も同時にあれば、そちらで YES になる。
- 修理者コメントの後ろの注記(「⭐️バッテリーが劣化しております」など)は今までどおり取り除くので、このコードにはならない。
- LENS は変わらない。

## 2. 手順

### 2-1. コードを新しい版に置き換え、テストを流す
```
python -m pytest tests/v2 -q
```
> 確認: **216 passed**

### 2-2. YAML に新しいコードを6つ足し、説明文を3つ直す
**ローカルの YAML に手を加えていない場合**: リポジトリの `config\classification_codes.yaml` で、ローカルの `classification_codes.yaml` を置き換える。

**手を加えている場合**: 次の6コードを足し、3コードの説明文を直す(Excel で行うなら `codes-export` → 各製品のシートで行の追加・説明文の修正 → `codes-import`)。説明文は、リポジトリの `config\classification_codes.yaml` から同じコードの `description` をコピーする。

| 製品のシート | コード | 名称 | 記録区分 | 責任区分 | 役割 |
|---|---|---|---|---|---|
| ML | M051 | 充電器不良 | failure | user_or_unknown | (空) |
| ML | M052 | バッテリー不良 | failure | user_or_unknown | (空) |
| ML | M053 | バッテリー劣化(寿命) | failure | user_or_unknown | (空) |
| DC | D051 | 充電器不良 | failure | user_or_unknown | (空) |
| DC | D052 | バッテリー不良 | failure | user_or_unknown | (空) |
| DC | D053 | バッテリー劣化(寿命) | failure | user_or_unknown | (空) |

説明文を直すコード: M047(接続機器要因)、D046(接続機器要因)、D002(充電不良)。

```
python repclass_cli.py check --local-dir C:\work\repclass_local
```
> 確認: 置き換えた場合は `version=0.5.3 製品=ML(54), LENS(43), DC(53)`。足した場合は、ML・DC のコード数が3つずつ増えていること。

### 2-3. プロンプトを更新し、Dify に貼り直す
**ローカルのプロンプトに手を加えていない場合**: リポジトリの `config\prompts\v2\system_prompt.md` で、ローカルの `prompts\system_prompt.md` を置き換える。

**手を加えている場合**: リポジトリの `config\prompts\v2\system_prompt.md` から、次の2か所をコピーして、ローカルのプロンプトの同じ場所に足す。
1. 「## 2. user_code」の「ユーザが充電器・バッテリーそのものの不具合に触れている番号…」の行
2. 「## 5. repair_code」の「**充電器・バッテリーが原因の場合**」の段落と例3つ

最後に、`---` より下を Dify の LLM ノードの SYSTEM に貼り直し、公開する。

### 2-4. 架空データで通しの確認をする
> 確認: `dry-run: 入力 64 / 除外 2 / 送信予定 62 / バッチ 7`。本実行で `error 0`。
- 新しいシナリオは T059〜T064(`tests\fixtures\synthetic\README.md`)。評価で外れていないかを見る。

### 2-5. 実データで確かめる
少量で実行し、次を確かめる。
- 純正の充電器・バッテリーの不良の修理が M051 / M052(D051 / D052)で、NO になっていること
- バッテリーの劣化・寿命が原因の修理が M053 / D053 で NO になっていること
- 他社製・互換品、汎用の USB 充電器が原因の修理が、接続機器要因のままになっていること
- 他社製なのに修理者コメントにそう書かれておらず、純正とみなされてしまう例が無いか(あれば、どんな書き方かを架空の文に言い換えて Mac 側に伝える)
